# AGENTS.md

Guidance for AI coding agents working in the Aespa repository.

## Overview

Aespa is a Swift package that wraps AVFoundation to make iOS video and photo
capturing simple. It supports both UIKit and SwiftUI, exposes Combine publishers
and async/await APIs, and handles camera permissions and session configuration.

- **Language / platform:** Swift 5.5+, iOS 14.0+
- **Dependencies:** none (AVFoundation / Combine only)
- **Distribution:** Swift Package Manager

## Project layout

```
Sources/Aespa/
  Aespa.swift          # Top-level factory / entry point
  AespaSession.swift   # Core session class
  AespaOption.swift    # Configuration options
  AespaError.swift     # Error types
  Core/                # Session, camera, recorder, album manager (+ Representable protocols)
  Data/                # Asset, Event, File, Proxy data structures
  Processor/           # Asset / Capture / File / Record processors
  Tuner/               # Chainable configuration tuners (Session, Device, Connection)
  Loader/              # Asset loaders
  Util/                # Extensions, File, Log, Authorization, Album helpers
  View/                # SwiftUI integration
  Aespa.docc/          # DocC documentation bundle
Tests/
  TestHostApp.xcodeproj  # Host app project used to run tests
  Test.xctestplan        # Test plan
  Tests/                 # XCTest sources (Tuner, Util, Processor, Mock)
  ExampleCode/           # Source of README code snippets
Demo/Aespa-iOS/          # Reference SwiftUI demo app
Scripts/                 # Mock generation, README updater, version
```

Start with `Aespa.swift` (factory) and `AespaSession.swift` (core logic).

## Build & test

Build the library:

```bash
xcodebuild build -scheme 'Aespa' -destination 'generic/platform=iOS'
```

Run tests (same command CI runs — see `.github/workflows/test.yml`):

```bash
xcodebuild test \
  -project Tests/TestHostApp.xcodeproj \
  -scheme TestHostApp \
  -testPlan Test \
  -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.5' \
  -derivedDataPath .build/DerivedData \
  -resultBundlePath .build/TestResults.xcresult \
  CODE_SIGNING_ALLOWED=NO
```

Build documentation:

```bash
./build-doc.sh
```

CI (`test.yml`) runs the test command above on every pull request and on pushes
to `main`. Make sure tests pass locally before opening a PR.

## Mocks

Mocks are generated by Cuckoo into `Tests/Tests/Mock/GeneratedMocks.swift`
(which is git-ignored). Do not edit that file by hand. Regenerate it after
changing mocked sources:

```bash
Scripts/gen-mocks.sh
```

## README code snippets

README code blocks are injected from `Tests/ExampleCode/` by
`Scripts/update_readme.py`. To change a README example, edit the corresponding
file under `Tests/ExampleCode/` and re-run the script — do not edit the snippet
directly in `README.md`.

```bash
python Scripts/update_readme.py
```

## Conventions

- Follow `.swiftlint.yml`: 120-column lines, no `force_cast`, document public
  API with `///` DocC comments (`missing_docs` is enabled).
- Keep the existing design patterns: chainable `Tuner` configuration, the
  `Representable` protocols that make Core testable, Combine + async/await APIs.
- Preserve Swift 6 concurrency annotations (`Sendable`, `MainActor`,
  `nonisolated`) when touching session/threading code.

## Agent working rules

- Do **not** put agent identifiers such as `codex` or `claude` anywhere in
  branch or git worktree names (including prefixes).
- Do **not** add `Co-authored-by:` trailers — or any other co-author
  attribution — to commit messages.
